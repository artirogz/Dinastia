# 10 — Как работать с Claude Code на этом проекте

Один разработчик, подписка Claude, macOS. Цель: получать рабочий код, тратя меньше токенов и не
теряя контроль над тем, что сделано.

## 1. Установка (один раз, macOS)

Руками ставится только Claude Code (`npm install -g @anthropic-ai/claude-code` или установщик с
сайта Anthropic). Node, Git, Docker (OrbStack), Playwright и `git init` делает сам Claude в скилле
`start-project`; владельца он попросит только о пароле для установщика Homebrew, если Homebrew нет.

Открыть папку проекта в терминале, запустить `claude` и вставить стартовый промпт:

```text
Начинаем работу над проектом. Это стартовый пакет: прочитай CLAUDE.md и PROJECT-STATE.md и действуй по скиллу start-project. Сначала проверь и доустанови окружение на этом Mac (Homebrew, Node 22 или новее, Git, Docker через OrbStack), сделай git init и первый коммит, потом задай мне все стартовые вопросы одним сообщением и собери каркас приложения до первого скриншота. Если чего-то не хватает и это могу сделать только я, назови ровно одну команду или действие и жди.
```

## 2. Модели: кто что делает

| Задача | Модель | Как переключить |
|---|---|---|
| Реализация по готовому документу, тесты, правки экранов | Sonnet | `/model sonnet` |
| Архитектурный вопрос, спека этапа, ревью кода перед слиянием | Opus | `/model opus` на время задачи, потом обратно |
| Поиск по коду «где это живёт» | агент `recon` (Haiku) | Claude вызывает сам, когда просишь найти |

По умолчанию держи Sonnet. Opus включай на 15–30 минут для ревью этапа и выключай. Это даёт
большую часть качества за малую часть расхода.

## 3. Что экономит токены

- **Не вставляй файлы целиком в чат.** Назови путь, Claude прочитает сам ровно то, что нужно.
- **Не проси «прочитай весь проект».** `CLAUDE.md` уже маршрутизирует к нужному документу.
- **`/compact` после каждого этапа** и когда контекст перевалил за ~150 тысяч токенов (видно в
  статусной строке). Перед `/compact` попроси записать состояние в `PROJECT-STATE.md`.
- **Один этап — одна сессия.** Новая задача другого типа → новая сессия, а не продолжение старой на
  300 тысяч токенов.
- **Скриншоты только изменённых экранов.** `node scripts/visual-check.mjs --only lesson` вместо
  всех экранов.
- **Вопросы батчем.** Если Claude задаёт вопросы по одному, попроси собрать все сразу.
- **Ревью один раз на этап**, а не после каждого файла.

## 4. Процесс одной задачи

1. Формулируешь задачу одним абзацем: что должно измениться для пользователя.
2. Claude вызывает `dev-flow-lite`, объявляет трек (`T0`/`T1`/`T2`) и класс риска (`R0`/`R1`/`R2`),
   при неясности задаёт 2–3 вопроса.
3. Делает. Для экранов — `visual-fidelity-loop`: скриншот → сравнение с макетом → правка → снова.
4. Проверяет: `npm test`, `npm run typecheck`, для экрана скриншот, для R2 ещё ревью.
5. Показывает результат: что изменилось, чем проверено, что осталось.
6. Ты смотришь результат сам (экран на телефоне, оплата в тестовом магазине) и говоришь «принято».

## 5. Ревью без второго вендора

Полноценный независимый критик другой модели здесь не используется. Замена, достаточная для
этого проекта:

- На этапах R2 (M2, M4, M6, M7) открой **новую сессию** Claude на Opus и попроси:
  «Прочитай `docs/03-auth-and-security.md` и код в `src/lib/auth`, `src/app/api/auth`. Найди
  дефекты: способы получить чужую сессию, доступ без покупки, повторную выдачу доступа. На каждую
  находку — конкретный запрос, который её воспроизводит». Свежий контекст без истории правок
  находит то, что сессия-автор не видит.
- Находки чини в сессии-авторе, потом ещё один круг критика. Два круга обычно достаточно.

## 6. Что Claude делать не должен без твоего слова

- Запускать рассылку или прогрев на реальных пользователей.
- Применять миграцию на боевой базе (`infra/deploy.sh` делает это, запускаешь ты).
- Платить: создавать боевые платежи, менять настройки магазина ЮKassa.
- Удалять данные пользователей.
- Коммитить секреты. `.env*` в `.gitignore` с первого коммита.

## 7. Типичные ошибки и что с ними делать

| Симптом | Причина | Действие |
|---|---|---|
| Claude «сделал», но экран не похож на макет | не было скриншота | требуй скриншот в ответе; скилл `visual-fidelity-loop` |
| Правка в одном месте, баг остался в другом | починен экземпляр, не класс | спроси «где ещё так же?», пусть покажет `grep` |
| Тесты зелёные, оплата не выдаёт доступ | проверено на фикстуре | тестовый магазин ЮKassa и реальный вебхук |
| Долгие ответы, повторы | контекст переполнен | `/compact` или новая сессия |
| Claude уверенно пишет про библиотеку, код не компилируется | память устарела | попроси сверить с официальной документацией до кода |

## 8. Перед каждой сессией

Claude читает `PROJECT-STATE.md` сам. Ты говоришь, что хочешь получить к концу сессии, одним
предложением. В конце сессии: «Запиши состояние в PROJECT-STATE и скажи, что открыто».
