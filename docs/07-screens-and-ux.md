# 07 — Экраны, навигация, особенности WebView

Экраны воссоздаются по скриншотам владельца (`design/screens/`), а не по словам этого документа.
Здесь описан состав экранов, состояния и ограничения платформы. Если макета экрана нет, Claude
спрашивает владельца, а не придумывает (`design/README.md`).

## 1. Экраны

| Экран | Маршрут | Что на нём | Макет |
|---|---|---|---|
| Запуск | `/` | решает, куда вести: есть сессия → `/courses`, нет → вход по `initData`; показывает только индикатор загрузки | не нужен |
| Вход по ссылке | `/login?token=…` | для браузера вне Telegram: обмен одноразового токена на cookie, затем переход на `/courses`; при просроченной ссылке — текст «Ссылка устарела, запросите новую в боте» и кнопка «Открыть бота» | `01-login` |
| Список курсов | `/courses` | карточки курсов пользователя (обложка, название, прогресс), ниже блок «Другие курсы» с ценой и замком | `02-courses` |
| Курс | `/courses/[slug]` | обложка, описание, модули списком, уроки внутри с состоянием: пройден, текущий, доступен, закрыт; кнопка «Продолжить» ведёт на следующий непройденный урок | `03-course` |
| Урок | `/lessons/[id]` | плеер сверху, ниже вкладки (раздел 2), кнопки «Предыдущий» и «Следующий» | `04-lesson-video` … `08-lesson-discussion` |
| Профиль | `/profile` | имя и аватар из Telegram, общий прогресс, список курсов с процентами, ссылка на политику и оферту, кнопка «Открыть в браузере» (создаёт ссылку входа) | `09-profile` |
| Экран покупки | на странице курса без доступа и в ответ на 403 урока | описание курса, цена, кнопка «Купить в боте» (deep link `https://t.me/<bot>?start=course-<slug>`) | `10-paywall` |

Оплата проходит на странице ЮKassa, которую бот присылает ссылкой; внутри приложения платёжной формы нет,
и экран покупки только ведёт в бота (`04-payments-yookassa.md` §1). Какой канал продаж допустим по правилам
Telegram (внешняя оплата по ссылке или Telegram Stars) — вопрос Q10 в `PROJECT-STATE.md`, он решается до M4.

### Вкладки урока

| Вкладка | Содержимое | Источник |
|---|---|---|
| Видео | плеер `LessonPlayer`, название, длительность, отметка «пройден» | `getPlayback()` |
| Конспект | `lessons.body_md`, отрисованный с блоками `:::insight`, `:::warning`, `:::task` | база |
| Материалы | список файлов: название, размер, тип; нажатие открывает подписанную ссылку | `lesson_materials` |
| Задание | текст задания, поле ответа, статус и обратная связь; вкладки нет, если задания у урока нет | `assignments` |
| Обсуждение | дерево комментариев, лайки, жалоба, поле ввода | `comments` |

Активная вкладка живёт в URL (`?tab=notes`), чтобы скриншот и ссылка открывали нужное.

## 2. Навигация

- Нижняя панель из двух пунктов: «Курсы» и «Профиль». Видна на `/courses` и `/profile`, скрыта на
  уроке (экран занят плеером и вводом комментариев).
- Глубина: список курсов → курс → урок. На курсе и уроке показывается кнопка «Назад»: внутри Telegram
  это системная `BackButton` из SDK, вне Telegram — стрелка в шапке. Один компонент `BackControl`
  выбирает, что показать.
- Переходы без анимаций тяжелее 200 мс: WebView на слабых Android-устройствах их не вытягивает.
- Системная кнопка «Закрыть» Telegram не переопределяется. Подтверждение закрытия включается только
  при несохранённом ответе на задание или комментарии.

## 3. Состояния каждого экрана

Для каждого экрана реализуются и снимаются четыре состояния, помимо нормального.

| Состояние | Что показываем |
|---|---|
| Загрузка | скелетон формы экрана, не спиннер на пустом месте; видео и картинки не сдвигают вёрстку (задан `aspect-ratio`) |
| Пусто | список курсов без покупок: короткий текст и кнопка «Выбрать курс»; нет комментариев: «Начните обсуждение» |
| Ошибка | сообщение человеческим языком и кнопка «Повторить»; для 401 переход на вход, для сети — «Нет соединения» |
| Нет доступа | экран покупки (раздел 1) вместо контента; урок не отдаёт ни видео, ни конспект, ни материалы |

Состояние «нет доступа» воспроизводится без второго тестового пользователя: параметр
`?locked=1` принудительно рисует его, но только при `NODE_ENV !== "production"`. В проде параметр
игнорируется, настоящий статус определяет сервер.

## 4. Особенности Telegram WebView

Всё из списка либо обязательно в коде, либо проверено на живом устройстве. Версии SDK и имена
методов (`@tma.js/sdk-react`, актуальное имя пакета сверить в context7; пакет менялся между мажорными версиями) сверяются с актуальной
документацией перед использованием.

- **Cookie.** `SameSite=None; Secure; HttpOnly`, иначе вход «проходит», а следующий запрос уже
  без сессии (`03-auth-and-security.md` §2). Признак: после входа `GET /api/me` отдаёт 401.
- **Развернуть окно.** При старте вызвать `expand()` (в SDK — `viewport.expand()`), иначе приложение
  открывается на половину экрана. Затем `ready()` у мини-аппа, когда экран отрисован.
- **Свайп вниз закрывает приложение.** Отключить вертикальные свайпы (в SDK — `swipeBehavior`,
  `disableVertical`; в Bot API это `disableVerticalSwipes`, доступно с версии 7.7). Иначе прокрутка
  конспекта сворачивает приложение.
- **Высота экрана.** Не использовать `100vh`: клавиатура и панели Telegram меняют видимую область, и
  поля ввода оказываются под клавиатурой. Высоту брать из `window.visualViewport.height` (или из
  переменной `--tg-viewport-stable-height`, если её ставит SDK) и подписаться на `resize`
  у `visualViewport`. Поле комментария при фокусе прокручивается в видимую область
  (`scrollIntoView({ block: "center" })`).
- **Кнопка «Назад».** Только через SDK (`backButton.show()`, `onClick`), не через `history.back()`
  в обход: иначе системная кнопка и браузерная история расходятся.
- **Тема.** Цвета интерфейса берутся из дизайн-токенов владельца. Параметры темы Telegram
  (`themeParams`) используются только для того, что макет не задаёт, например фон при загрузке.
  Тёмная тема проверяется отдельным прогоном скриншотов, если макеты её содержат.
- **Тактильный отклик** (`hapticFeedback`) необязателен: на завершение урока и успешную отправку
  ответа, не на каждый тап.
- **Видео в полный экран.** На iOS WebView открывает системный плеер, и интерфейс приложения
  из него не виден. После выхода из полного экрана пользователь должен вернуться на тот же урок и ту же
  позицию; кнопка «Следующий урок» доступна именно там (`05-video-delivery.md` §5).
- **Фонового воспроизведения нет.** Свернул Telegram — видео остановилось. Интерфейс не обещает
  «слушать в фоне».
- **Безопасные зоны.** Отступы под вырез и жестовую панель: `env(safe-area-inset-*)` в CSS и, если SDK
  отдаёт, `safeAreaInsets` и `contentSafeAreaInsets` (при полноэкранном режиме шапка Telegram
  перекрывает верх). Нижняя панель навигации учитывает нижний отступ.
- **Эталонный размер.** 390×844 (iPhone 14/15). Вёрстка проверяется также на 360×740 (узкий
  Android) и 430×932; горизонтальной прокрутки нет ни на одном.
- **Работа вне Telegram.** Любой вызов SDK обёрнут в `tg.*`-хелперы, которые в обычном браузере
  ничего не делают и не бросают исключение (`isTMA()` ложно). Экран не должен ломаться оттого,
  что `window.Telegram` отсутствует: именно так он открывается по ссылке из бота в браузере и в
  `scripts/visual-check.mjs`.
- **Шрифты и картинки.** Шрифты грузятся с нашего домена (`font-display: swap`), не с зарубежных
  CDN: это и вопрос 152-ФЗ, и скорость при замедлении внешних ресурсов.
- **Ввод.** Размер шрифта поля не меньше 16 px, иначе iOS приближает страницу при фокусе.
- **Файлы.** Скачивание материала открывает ссылку с download-token (10 минут, привязан к пользователю
  и файлу) в системном браузере через `openLink`: в WebView iOS PDF показывается внутри окна без кнопки
  «назад». В системном браузере cookie WebView нет, поэтому `/api/media/[id]` проверяет токен, а не сессию.
  Ссылка с живым токеном работает у любого в эти 10 минут: признанный риск (`03-auth-and-security.md` §10).

## 5. Как скриншоты владельца превращаются в экраны

Владелец кладёт файлы в `design/screens/` по схеме `NN-<экран>.png` (подробно — `design/README.md`).
Соответствие номеров и маршрутов:

| Файл | Экран | Ключ маршрута в `scripts/visual-check.mjs` |
|---|---|---|
| `01-login.png` | вход по ссылке | `login` (маршрут `/login`, снимается без cookie) |
| `02-courses.png` | список курсов | `courses` |
| `03-course.png` | курс | `course` |
| `04-lesson-video.png` | урок, вкладка «Видео» | `lesson` |
| `05-lesson-notes.png` | урок, вкладка «Конспект» | `lesson_notes` |
| `06-lesson-materials.png` | урок, вкладка «Материалы» | `lesson_materials` |
| `07-lesson-assignment.png` | урок, вкладка «Задание» | `lesson_assignment` |
| `08-lesson-discussion.png` | урок, вкладка «Обсуждение» | `lesson_discussion` |
| `09-profile.png` | профиль | `profile` |
| `10-paywall.png` | экран покупки | `paywall` |

Порядок работы над экраном:

1. Прочитать макет (открыть PNG) и описать в двух-трёх строках, что на нём: блоки, шрифты, отступы,
   цвета. Заполнить недостающие токены в `design/README.md`.
2. Собрать экран на демо-данных из `content/courses/example-course`.
3. `node scripts/visual-check.mjs --only <ключ>` → скриншот в `design/visual-check/<метка>/`. До M2
   добавляй `--no-auth` (входа ещё нет); с M2 скрипт сам входит через `/api/dev/login`, который заводит
   пользователя «Dev» с доступом к `example-course` (`03-auth-and-security.md` §4), так что уроки в
   маршрутах скрипта — уроки этого курса.
4. Открыть скриншот и макет и сверить рядом: сетка, размеры текста, цвета, иконки, обрезка,
   состояние шрифтов. Расхождения исправить и повторить с шага 3, пока расхождения не кончатся.
5. Экран закрыт, когда отличия остались только в данных (имена, цифры), а не в вёрстке. Путь к
   финальному скриншоту записывается в `PROJECT-STATE.md`.

Нет макета продуктового экрана из таблицы §1 → вопрос владельцу с перечнем недостающих файлов. Рисовать
«примерно похоже» нельзя: потом это переделывается целиком. Служебные состояния (загрузка, пусто, ошибка,
нет доступа) макетов не требуют: они делаются нейтрально в стиле соседних экранов (`design/README.md`).
