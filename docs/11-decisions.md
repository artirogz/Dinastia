# 11 — Журнал решений

Записи только добавляются. Отменённое решение не удаляется, а помечается `заменено ADR-NNN`.
Формат: контекст → решение → альтернативы → последствия.

## ADR-001 — Вся инфраструктура на российском VPS (2026-10-07)

**Контекст.** Пользователи — граждане РФ, храним их идентификаторы, имена, покупки, прогресс.
Референсная реализация похожего продукта стояла на Supabase + Vercel + Cloudflare R2: всё за
границей.

**Решение.** PostgreSQL, файлы, логи, бэкапы — на VPS российского провайдера (Timeweb Cloud,
Beget или Selectel). Приложение в Docker Compose там же.

**Альтернативы.** Supabase/Vercel (быстрее старт, но нарушает требование локализации);
российский managed Postgres (дороже, на старте не нужен).

**Последствия.** Деплой и бэкапы на нас. Один `docker compose` и `deploy.sh`. Нет serverless-лимитов,
поэтому бот и воркер живут долгоживущими процессами.

## ADR-002 — Один Next.js на экраны, API и вебхук бота + отдельный worker (2026-10-07)

**Контекст.** Один разработчик с Claude Code. Нужны экраны, API, бот, фоновые задачи.

**Решение.** Монолит Next.js (App Router). grammY подключён в API-роут вебхука. Фоновые задачи в
отдельном процессе `worker` из того же образа на pg-boss.

**Альтернативы.** Отдельный API-сервер (Fastify/Nest) + SPA (два деплоя, CORS, дубль типов);
бот отдельным сервисом на long polling (ещё один процесс без выгоды при наличии домена).

**Последствия.** Один `package.json`, одна схема типов. Долгие задачи нельзя класть в запрос,
только в `worker`.

## ADR-003 — Видео через интерфейс провайдера, по умолчанию Kinescope (2026-10-07)

**Контекст.** YouTube в России замедлен и не защищает платный контент. Нужен плеер, который
играет из мобильных сетей РФ, и защита от передачи ссылок.

**Решение.** `VideoProvider` с адаптерами `kinescope` и `hls`. По умолчанию Kinescope: DRM,
авторизация доступа через наш бэкенд, водяной знак. Решение подтверждается прототипом на этапе M3
(таблица проверок в `05-video-delivery.md` §6).

**Альтернативы.** Своё HLS на российском S3 (дешевле, без DRM, эксплуатация на нас); Boomstream
(рубли, защита по сессиям, DRM не подтверждён); Rutube/VK (ссылка передаётся, нет контроля доступа).

**Последствия.** Урок хранит `video_provider` и `video_ref`. Смена хостинга = адаптер +
перезаливка, без изменения экранов. Открытые проверки: воспроизведение в WebView iOS, оплата из РФ.

## ADR-004 — Вход по `initData` с одноразовостью подписи и cookie `SameSite=None` (2026-10-07)

**Контекст.** Mini App живёт во фрейме Telegram. Подпись `initData` можно перехватить и предъявить
позже.

**Решение.** Проверка HMAC на сервере, TTL 5 минут, одноразовость `hash` с исключением для
повтора с cookie того же пользователя, httpOnly-cookie `SameSite=None; Secure`, CSRF-сторож по
`Origin`. Дополнительный вход из браузера по одноразовой ссылке из бота.

**Альтернативы.** Хранить `tg_id` в localStorage и слать в заголовке (подделывается);
Telegram Login Widget (зависит от скрипта с домена Telegram).

**Последствия.** Таблицы `init_data_uses`, `magic_links`. Ручка `/api/dev/login` для разработки без
телефона, отсутствует в проде по построению.

## ADR-005 — ЮKassa с вебхуком и фоновой сверкой, идемпотентная выдача доступа (2026-10-07)

**Контекст.** Вебхуки ЮKassa настраиваются в личном кабинете, не через API магазина; при сбое
доставки оплата «теряется» (деньги списаны, доступ не выдан).

**Решение.** Вебхук и сверка каждые 5 минут зовут один `handleOrderPaid()`; выдаёт доступ только
вызов, который атомарно перевёл заказ `pending → succeeded`. Тело вебхука не считается истиной:
платёж перечитывается по id через API.

**Альтернативы.** Telegram Stars (вывод через Fragment в TON, чеков 54-ФЗ нет, курс звезды задаёт
Telegram); Prodamus/CloudPayments (возможны позже как второй адаптер).

**Дополнение (2026-10-07, правила Telegram).** Правила Bot API для платежей говорят: «Payments for digital
goods and services must be carried out exclusively in Telegram Stars» внутри Telegram, включая мини-приложения,
и это не зависит от того, какой провайдер подключён (https://core.telegram.org/bots/payments-stars). Онлайн-курс
— цифровая услуга. Оплата на внешней странице ЮKassa, которую бот присылает ссылкой, происходит вне Telegram,
но допустимость такого перехода для бота формально не подтверждена. Два варианта: (а) ЮKassa по ссылке
наружу — чеки 54-ФЗ, рубли на счёт, риск претензий со стороны Telegram; (б) Stars — внутри правил, но без
чеков и с выводом через TON. По тексту тех же правил Telegram может не показывать бота и мини-приложение мобильным пользователям, если
цифровые товары продаются через сторонних провайдеров; известных случаев применения этого к российским ботам
с внешней оплатой на 2026-10-07 не найдено, но и подтверждения допустимости нет. Выбор за владельцем
(вопрос Q10) после «Проверок первой недели» (`08-roadmap.md`), до начала M4; пока принято допущение (а). Архитектура от выбора не меняется: `createPayment()` и `handleOrderPaid()` остаются, Stars —
второй адаптер провайдера с `payment_id` = `telegram_payment_charge_id`.

**Последствия.** Таблица `orders` с `payment_id`, `status`, `receipt_contact`. Повторный вебхук и
гонка с поллером безопасны по построению.

## ADR-006 — Контент файлами в репозитории, админка после запуска (2026-10-07)

**Контекст.** На старте пять курсов. Админ-панель — отдельный большой этап, а первые продажи
нужны раньше.

**Решение.** `content/courses/<slug>/course.yaml` + `lessons/NN-slug.md`; идемпотентный импорт в базу.
Прогревы так же: `content/funnels/<slug>.yaml`. Админ-панель — этап M8 после первых продаж.

**Альтернативы.** Админка с первого дня (дорого, требования неизвестны); headless CMS (ещё один
сервис, персональных данных там нет, но и выгоды мало).

**Последствия.** Владелец правит markdown в редакторе. Изменение контента = коммит + импорт.
Модерация комментариев и выдача доступа — командами бота до появления админки.

## ADR-007 — Приложение работает и вне Telegram (2026-10-07)

**Контекст.** Telegram в России замедляют с февраля 2026 года; обсуждается полное ограничение.

**Решение.** Mini App — обычное веб-приложение на своём домене. Внутри Telegram вход по `initData`,
снаружи по одноразовой ссылке из бота. Экраны не зависят от Telegram SDK: его вызовы
(`expand`, тема, кнопка «Назад») обёрнуты и отключаются вне WebView.

**Последствия.** Проверка макетов идёт в обычном браузере в 390×844. Если Telegram станет недоступен,
обучение продолжится в браузерах, где cookie уже есть (30 дней, продлевается при активности). Новую ссылку
входа выдаёт только бот, поэтому вход с нового устройства без Telegram потребует отдельного канала
восстановления (например, по email или телефону из заказа). Это решение после запуска, в этапы не входит.
