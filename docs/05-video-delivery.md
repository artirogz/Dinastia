# 05 — Видео: провайдер, защита, плеер

## 1. Требования

- Играет в России с мобильных сетей без VPN, внутри Telegram WebView на iOS и Android и в обычном
  браузере.
- Видят только купившие. Ссылку на видео нельзя передать другу так, чтобы она работала.
- Владелец загружает видео сам, без участия разработчика.
- Переход на другой хостинг не требует переделки уроков.

YouTube исключён: с 2024 года в России он замедлен, в 2026 году ограничения колеблются от 50 до 75 %
аномальных измерений по месяцам, а ссылка на непубличное видео передаётся кому угодно.

## 2. Решение: интерфейс провайдера + два адаптера

```ts
// src/lib/video/provider.ts
export interface VideoProvider {
  /** Что нужно клиенту, чтобы начать воспроизведение этого урока этим пользователем. */
  getPlayback(input: { videoRef: string; userId: number; lessonId: number }): Promise<Playback>;
  /** Длительность и статус обработки по ссылке на видео у провайдера (для импорта контента). */
  describe(videoRef: string): Promise<{ durationSec: number; ready: boolean }>;
}

export type Playback =
  | { kind: "kinescope"; videoId: string; authToken: string; expiresAt: string }
  | { kind: "hls"; manifestUrl: string; expiresAt: string };
```

Урок хранит `video_ref` (строка провайдера) и `video_provider`. Клиентский компонент `LessonPlayer`
переключается по `kind`. Смена хостинга = новый адаптер + перезаливка видео + обновление
`video_ref` в контенте.

## 3. По умолчанию: Kinescope

Видеохостинг для курсов с двумя контурами: kinescope.ru (российское юрлицо, тарифы в рублях, хранение в РФ) и
kinescope.com (Kinescope B.V., Нидерланды, евро, данные в ЕС). Для 152-ФЗ подходит только первый: договор
и кабинет заводятся на kinescope.ru, юрлицо из оферты записывается в `PROJECT-STATE.md` (Q5). Авторизация
просмотра через наш бэкенд и поведение плеера в Telegram на iOS проверяются пробой в первую неделю
(`08-roadmap.md`, «Проверки первой недели»), не на M3. Что даёт (по документации на 2026-10-07):

- Плеер через iframe или Player SDK, адаптивное качество, своя CDN.
- Защита: ограничение доменов встраивания, DRM (Widevine, FairPlay), динамический водяной знак
  с данными зрителя, **авторизация доступа через наш бэкенд**: плеер получает `drmauthtoken`,
  Kinescope спрашивает наш URL, мы отвечаем 200 или 403.
- API загрузки и список видео.
- Тарифы (docs.kinescope.ru, 2026-10-07): минимальный платный «Super» от 700 ₽/мес, дальше по объёму:
  хранение 1,9 ₽/ГБ, трафик CDN 1,9 ₽/ГБ за первые 1 000 ГБ (следующие ступени дешевле), транскодирование
  0,8 ₽/мин. Оплата картой РФ, для юрлиц по счёту. Какой тариф включает DRM и авторизацию через бэкенд —
  сверить в кабинете.
- Оценка расходов по одной методике для всех вариантов (720p ≈ 1 ГБ на час видео): 10 курсов по 10 часов
  → 100 ГБ хранения ≈ 190 ₽/мес; 300 учеников по 10 часов просмотра в месяц ≈ 3 ТБ трафика ≈ 5,7 тыс ₽/мес;
  1 000 учеников ≈ 10 ТБ ≈ 19 тыс ₽/мес по ставке первой ступени (реальная ниже за счёт ступеней).

**Что не подтверждено и проверяется прототипом на первом этапе:**

1. Воспроизведение в Telegram WebView на iOS: старые отчёты (2022–2023) говорят, что `<video>` в
   WebView iOS открывается только на весь экран и без автоплея. Проверить iframe Kinescope на живом
   iPhone и Android в сетях МТС, Билайн, Мегафон до того, как заливать все курсы.
2. Условия договора для ИП/самозанятого и наличие DRM и авторизации через бэкенд на выбранном тарифе:
   проверить в кабинете до заливки курсов.

Если пункт 1 проваливается на iOS, запасной план в том же адаптере: открывать плеер на весь экран
через Bot API `requestFullscreen()` или отдельной вкладкой в браузере (ссылка из приложения).

### Как подключено

- `video_ref` = id видео в Kinescope. Владелец загружает ролик в кабинет, копирует id в
  `lessons/NN.md`.
- `getPlayback()` выписывает JWT на 10 минут с `lessonId`, `userId` (числовой внутренний id, не
  `tg_id`) и подписью `KINESCOPE_AUTH_SECRET`. Плеер передаёт его Kinescope, Kinescope зовёт
  `POST /api/video/authorize` на нашем домене, мы проверяем подпись и срок токена, совпадение id видео из
  запроса с `video_ref` урока из токена и доступ к этому уроку через `requireLessonAccess(userId, lessonId)`
  (`03-auth-and-security.md` §5). Ручка стоит в исключениях cookie/CSRF (`03` §2): её зовёт сервер
  хостинга, а не браузер. Хостинг получает токен (внутренние id, читаются без ключа; имени и `tg_id` нет)
  и, как любой веб-сервер, IP и User-Agent зрителя — это записано в реестре получателей (`03` §8).
- Домен встраивания ограничен `app.<домен>`.
- Водяной знак: включать на тарифе, где он есть. Текст знака — внутренний id пользователя, чтобы
  утечку можно было связать с аккаунтом, не раскрывая имени.

## 4. Запасной путь: своё HLS

Когда: бюджет на хостинг не согласован, или Kinescope не прошёл проверку в WebView, или владелец
хочет полный контроль.

```
исходник.mp4 → ffmpeg (720p + 480p, сегменты 6 с, AES-128 опционально) → каталог на российском S3
(Selectel, Timeweb, Яндекс) → публичная раздача через CDN провайдера → манифест выдаётся
приложением по подписанной ссылке на 10 минут
```

- Плеер: `hls.js` на Android и десктопе, нативный HLS в Safari/iOS (там `hls.js` работает через
  ManagedMediaSource с iOS 17.1; на старых iOS отдаём нативный `<video src=…m3u8>`).
- Защита: подпись должна покрывать весь префикс урока, манифест и сегменты (`secure_link` на префикс
  пути с TTL или раздача сегментов через наш прокси), иначе подписанный манифест защищает только сам
  манифест, а сегменты остаются публичными. Ссылка с живой подписью работает у любого, кому её передали,
  до истечения TTL (10 минут): это уровень ниже DRM, он защищает от хотлинка, не от записи экрана и не от
  передачи ссылки «здесь и сейчас». Для курсов до нескольких тысяч рублей обычно достаточно; нужно строже
  → Kinescope с DRM.
- Цена: хранение ~2,4–2,6 ₽/ГБ/мес, трафик ~1,3–1,7 ₽/ГБ. При 1 000 студентах и 10 часах просмотра в
  месяц это около 9 ТБ и 12–15 тыс ₽ в месяц. При 300 студентах — около 4 тыс ₽.
- Трудоёмкость: пайплайн транскодирования, загрузка, мониторинг хранилища. Всё на владельце.

Промежуточный вариант — Boomstream (российский, тарифы в рублях от 2 200 ₽/мес, защита по домену и
сессиям, без подтверждённого DRM). Рассматривать, если Kinescope не согласуется по оплате.

## 5. Плеер в приложении

- Один компонент `LessonPlayer` на оба адаптера. Снаружи он отдаёт события `timeupdate`, `ended`,
  `error` в хук прогресса.
- Атрибуты `playsinline`, `controls`, без автоплея (в WebView он всё равно заблокирован).
- Прогресс: позиция сохраняется каждые 10 секунд и при `visibilitychange`/закрытии. Урок пройден
  при 90 % длительности. Длительность берётся из `describe()` при импорте, не с клиента.
- Фоновое воспроизведение в Telegram WebView прерывается при сворачивании: это ограничение
  платформы. В интерфейсе не обещаем «слушать в фоне».
- Полный экран: iOS в WebView открывает системный плеер. Поверх него интерфейс приложения не
  виден. Кнопка «Следующий урок» должна быть доступна после выхода из полного экрана.

## 6. Что проверяем на этапе прототипа (до заливки курсов)

| Проверка | Как | Критерий |
|---|---|---|
| iPhone, Telegram, МТС | открыть урок с реальным видео Kinescope | старт за ≤ 3 с, перемотка работает, полный экран возвращает в урок |
| Android, Telegram, Билайн | то же | то же |
| Браузер Safari/Chrome по magic-ссылке | то же | то же |
| Передача ссылки другу | скопировать URL манифеста/iframe и открыть в другом браузере | 403 или ошибка плеера |
| Пользователь без покупки | открыть урок по прямому `lesson id` | 403 от API, плеер не получает токен |

Результаты записываются в `PROJECT-STATE.md` как замер с датой, после чего решение «Kinescope или
HLS» фиксируется в `docs/11-decisions.md`.
