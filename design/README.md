# design/: макеты и дизайн-токены

Экраны воссоздаются по скриншотам владельца продукта. Claude не придумывает вид экрана: нет макета,
значит, вопрос владельцу (список экранов и состояний ниже).

## Что и как класть в `design/screens/`

Формат: PNG, снимок с телефона или из дизайн-инструмента в ширину 390 pt (или 1170 px при
плотности ×3), без рамки устройства и без строки состояния, если можно. Если снимок длиннее экрана,
это нормально: экран снимается целиком (`fullPage`), сверка идёт по всей длине.

Имена файлов `NN-<экран>.png`, номера фиксированы, потому что на них завязаны ключи в
`scripts/visual-check.mjs` (`docs/07-screens-and-ux.md` §5):

| Файл | Экран | Нужно ли |
|---|---|---|
| `01-login.png` | вход по ссылке из браузера, в том числе «Ссылка устарела» | да |
| `02-courses.png` | список курсов | да |
| `03-course.png` | курс: модули и уроки с состояниями | да |
| `04-lesson-video.png` | урок, вкладка «Видео» | да |
| `05-lesson-notes.png` | урок, вкладка «Конспект» с блоками «Важная мысль», «Осторожно», «Задание» | да |
| `06-lesson-materials.png` | урок, вкладка «Материалы» | да |
| `07-lesson-assignment.png` | урок, вкладка «Задание» | да |
| `08-lesson-discussion.png` | урок, вкладка «Обсуждение» | да |
| `09-profile.png` | профиль | да |
| `10-paywall.png` | экран покупки | да |

Если на какой-то экран макета нет, напиши об этом в `PROJECT-STATE.md` (вопрос Q6). Состояния
«загрузка», «пусто», «ошибка» (`docs/07-screens-and-ux.md` §3) отдельными макетами не обязательны:
если их нет, Claude рисует их нейтрально в стиле соседних экранов и пишет об этом в отчёте.

Дополнительные файлы (второе состояние того же экрана, тёмная тема) называй так же с суффиксом:
`02-courses-empty.png`, `02-courses-dark.png`. Главное правило: по имени файла понятно, какой экран
и какое состояние.

## Токены дизайна

Заполняется владельцем или Claude по макетам (Claude читает цвета и размеры со скриншотов и записывает
сюда догадки с пометкой «по макету»). Пустая ячейка означает «взять нейтральное значение».
Из этой таблицы собираются CSS-переменные в `src/app/globals.css`; в компонентах цвета и размеры
не пишутся числами.

| Токен | Значение | Источник |
|---|---|---|
| `--color-bg` (фон экрана) | | |
| `--color-surface` (карточки) | | |
| `--color-text` | | |
| `--color-text-muted` | | |
| `--color-accent` (кнопки, активная вкладка) | | |
| `--color-accent-text` (текст на акценте) | | |
| `--color-border` | | |
| `--color-success` (урок пройден) | | |
| `--color-danger` | | |
| Шрифт (заголовки / текст) | | |
| Размеры текста (заголовок, подзаголовок, основной, мелкий) | | |
| Скругления (карточка, кнопка, поле) | | |
| Базовый шаг отступов | | |
| Тёмная тема | нужна / не нужна | |

Шрифты загружаются с нашего домена, не с зарубежных CDN (`docs/07-screens-and-ux.md` §4). Если
фирменный шрифт платный, нужен файл с лицензией на веб; если его нет, до решения подставляется
системный.

## Как сверяется экран

Скилл `visual-fidelity-loop`. Одним абзацем: `node scripts/visual-check.mjs --only <ключ>` снимает
экран в 390×844 с плотностью ×2, Claude открывает полученный PNG и макет, перечисляет расхождения
(сетка, размеры текста, цвета, иконки, обрезка, шрифты) и правит, пока отличия не останутся только
в данных. Результаты лежат в `design/visual-check/<метка>/` и коммитятся как доказательство.

## Что владельцу стоит знать

1. На макетах не должно быть реальных имён, фото и контактов учеников: макеты читает Claude и они
   коммитятся в репозиторий. Подставь вымышленные данные или замажь. Цены и названия курсов оставляй:
   в экранах Claude всё равно использует демо-данные из `content/courses/example-course`.
2. Меняется макет после реализации экрана: пришли новый файл с тем же именем и напиши, что
   поменялось. Старый переименуй в `NN-<экран>-old.png`, не удаляй.
3. Анимации и переходы по скриншотам не видны. Если они важны, опиши словами в `PROJECT-STATE.md`.
