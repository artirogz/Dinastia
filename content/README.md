# content/: курсы, прогревы, рассылки файлами

Контент живёт в git, а не в админке. Владелец правит текст в редакторе, разработчик (или Claude)
запускает импорт. Расшифровка, в какие таблицы что попадает, и правила импорта: `docs/02-data-model.md` §6.

```
content/
  courses/<slug>/
    course.yaml
    lessons/NN-<slug>.md
    materials/            файлы для скачивания (PDF и т.п.)
  funnels/<slug>.yaml     цепочки прогрева (формат: docs/06-bot-and-funnels.md §5)
  broadcasts/<slug>.yaml  разовые рассылки (формат: docs/06-bot-and-funnels.md §8)
```

Импорт:

```bash
npm run content:import             # all courses and funnels
npm run content:import -- --dry-run   # print what would change, write nothing
```

Импорт идемпотентный: повторный запуск на тех же файлах ничего не меняет (сравнивается `content_hash`).
Ключи `--dry-run` и имя команды определяются при создании скрипта `scripts/import-content.ts`.

На сервере npm-скриптов в образе нет, импорт запускается готовым файлом из сборки `build:server`,
после деплоя (контент попадает в образ при сборке):

```bash
docker compose -f infra/docker-compose.yml --env-file infra/.env run --rm web node dist/scripts/import-content.js
```

## course.yaml

| Поле | Обязательно | Значение |
|---|---|---|
| `slug` | да | латиница, цифры, дефис; совпадает с именем папки; после первого импорта не меняется |
| `title` | да | название курса |
| `subtitle` | нет | строка под названием |
| `description` | нет | markdown-описание для экрана курса и экрана покупки (`courses.description`) |
| `cover` | нет | имя файла обложки в папке курса (`cover.png` или `.jpg`); импорт кладёт его под `MEDIA_ROOT` и пишет ключ в `courses.cover_key`; файла нет → предупреждение в выводе импорта, курс без обложки |
| `price_minor` | да | цена в копейках, целое число (4 900 ₽ = `490000`) |
| `access_days` | нет | срок доступа в днях; `null` или поле не указано = бессрочно |
| `unlock_mode` | нет | `all` (по умолчанию) или `sequential` (следующий урок после прохождения предыдущего) |
| `status` | нет | `draft` (по умолчанию) или `published`; черновик ученикам не виден |
| `modules` | да | список `{ slug, title }`; порядок в списке = порядок на экране |

## lessons/NN-slug.md

Имя файла: два-три цифры порядка, дефис, slug урока: `01-intro.md`. Число из имени задаёт порядок
внутри курса. Slug урока уникален в пределах курса.

Заголовок файла (frontmatter):

| Поле | Обязательно | Значение |
|---|---|---|
| `title` | да | название урока |
| `module` | да | slug раздела из `course.yaml` |
| `status` | нет | `draft` (по умолчанию) или `published` |
| `video_provider` | да | `kinescope` или `hls` |
| `video_ref` | да | для `kinescope`: id видео из кабинета; для `hls`: путь к плейлисту относительно `MEDIA_ROOT` |
| `duration_sec` | нет | длительность в секундах; провайдер может уточнить |
| `materials` | нет | список `{ title, file }`; `file` относительно папки курса |
| `assignment` | нет | `{ submission_type, prompt }`; `submission_type`: `text`, `file` или `text_or_file` |

Тело файла: конспект в markdown. Кроме обычной разметки поддерживаются три блока:

```
:::insight
Главная мысль урока.
:::

:::warning
Типичная ошибка.
:::

:::task
Короткое практическое действие.
:::
```

## Правила

1. Видео в репозиторий не кладётся. Для Kinescope загрузи ролик в кабинет и вставь id в `video_ref`.
2. Файл материала должен существовать на диске, иначе импорт падает с указанием урока.
3. Убрал урок из папки: он не удаляется из базы, а становится черновиком (на нём висят прогресс и
   комментарии), импорт печатает предупреждение.
4. Урок нельзя перенести в другой курс правкой файла: создай новый.
5. Перед выкатом на боевой сервер импорт прогоняется локально, а на сервере запускается один раз
   после деплоя.
6. Рассылки и цепочки импорт только загружает; отправка стартует по команде администратора в боте.
