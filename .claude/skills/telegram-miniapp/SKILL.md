# Telegram Mini App: правила, которые дорого переоткрывать

Каждый пункт здесь был настоящим багом на похожем продукте. Проверяй по этому списку до того, как
искать причину в данных или в обработчиках.

## 1. Вход и cookie

- **Cookie во фрейме живёт только как `SameSite=None; Secure`.** Telegram показывает Mini App во
  фрейме. Cookie с `Lax` браузер выбрасывает молча: вход возвращает 200, следующий запрос — 401,
  снаружи это выглядит как «ничего не нажимается». Атрибуты выбираются по протоколу запроса
  (`x-forwarded-proto === "https"`), а не по `NODE_ENV`: сборка не знает, что снаружи HTTPS-туннель.
- **Клиент сначала пробует cookie, потом `initData`.** `GET /api/me` → 401 → `POST /api/auth/session`
  с `initData`. Иначе каждая перезагрузка тратит одноразовую подпись и ломает повтор.
- **Проверка подписи — только на сервере**, токен бота в клиент не уходит. TTL `auth_date` 5 минут.
  Повтор того же `hash` принимается только с cookie того же пользователя.
- **`tg_id` из тела запроса не принимается никогда.** Только из проверенной сессии.
- **CSRF.** Cookie `SameSite=None` уходит с любого сайта → изменяющие ручки проверяют `Origin` или
  `Sec-Fetch-Site` против своего домена.

## 2. Разработка без телефона

`POST /api/dev/login` подписывает `initData` тем же алгоритмом, что Telegram, и прогоняет через ту
же проверку. Существует только при `NODE_ENV !== "production"` **и** `DEV_LOGIN=1`. Так Playwright
снимает экраны, а разработчик кликает в обычном браузере. Для проверки на телефоне без деплоя —
HTTPS-туннель (`cloudflared tunnel --url http://localhost:3000` или `ngrok`) и адрес туннеля в
BotFather как URL Mini App; **туннель обслуживает прод-сборку (`npm run build && npm start`)**, не
`next dev`: dev-сервер под нагрузкой WebView роняет воркер, и снаружи это выглядит как 500 на уроке.
Через туннель ходят только тестовые аккаунты разработчика: трафик идёт через сервер Cloudflare или ngrok
за пределами РФ. Адрес туннеля ставится в BotFather у тестового бота, не у боевого, и реальных учеников
туда не пускаем.

## 3. Экран и вьюпорт

- **`expand()` при старте**, иначе приложение открывается на половину экрана. Вертикальные свайпы
  отключить (`disableVerticalSwipes()`), иначе прокрутка списка сворачивает приложение.
- **Высота — по `visualViewport`, не `100vh`.** Клавиатура уменьшает видимую область, а `100vh`
  нет: поле ввода комментария уезжает под клавиатуру. Корневой контейнер берёт высоту из
  `window.visualViewport.height` и подписывается на `resize`.
- **Safe areas** через `env(safe-area-inset-*)` и параметры SDK (`contentSafeAreaInset`), иначе
  нижняя навигация под системной полосой iPhone.
- **Тема** из `themeParams` только как переопределение токенов; базовая палитра своя, иначе
  экраны в тёмной теме Telegram разваливаются.
- **Кнопка «Назад»** — через SDK (`backButton`), не браузерная история. Вне Telegram SDK-вызовы
  обёрнуты и ничего не делают: приложение обязано работать по обычной ссылке.
- Референсный вьюпорт для скриншотов — **390×844, deviceScaleFactor 2**.

## 4. Видео в WebView

- iOS в WebView открывает `<video>` в системном полноэкранном плеере; интерфейс приложения в этот
  момент не виден. Кнопка «Следующий урок» должна быть под плеером после выхода.
- Автоплей заблокирован. Не обещать и не пытаться.
- Фоновое воспроизведение прерывается при сворачивании Telegram. Это свойство платформы.
- `playsinline` ставить всегда: на Android и в браузере он даёт инлайн-воспроизведение.
- Проверка на живом iPhone и Android в мобильной сети — часть этапа M3, не «потом».

## 5. Прокрутка и память места

- Режимы одного экрана (видео / конспект / материалы) с разной высотой делят контейнер прокрутки.
  При переключении браузер **подрезает** прокрутку по новой высоте и присылает обычный `scroll`,
  неотличимый от чтения. Позиция сохраняется по ключу «урок + режим» и восстанавливается после
  монтирования содержимого, а события в первые ~300 мс после переключения игнорируются.
- Длинный конспект открывается сверху, а не на случайной позиции предыдущего режима.

## 6. Вебхук бота

- `setWebhook` с `secret_token`; роут отвергает запросы без заголовка
  `X-Telegram-Bot-Api-Secret-Token`.
- Ответ Telegram за ≤ 10 с, иначе ретрай. Долгое (рассылка, импорт) — в `worker`, не в обработчике.
- Ретраи Telegram и двойные нажатия на inline-кнопку — норма: обработчики `callback_query`
  идемпотентны, `answerCallbackQuery` вызывается всегда.
- Бот не может написать пользователю, который не нажимал Start (`chat not found`), и получает 403
  от заблокировавшего (`bot was blocked`). Оба случая помечаются в `users`, цепочка прогрева
  останавливается.
- Модерационные обработчики монтируются **до** catch-all обработчика `callback_query`.

## 7. Чек-лист перед закрытием экрана

- [ ] Открывается на весь экран, свайп вниз не сворачивает.
- [ ] После перезагрузки страницы сессия жива (cookie, а не повтор `initData`).
- [ ] Клавиатура не закрывает поле ввода (проверено на iPhone).
- [ ] Экран работает по обычной ссылке в Safari/Chrome.
- [ ] Скриншот 390×844 сошёлся с макетом (`visual-fidelity-loop`).
