# Visual Fidelity Loop: отрендерь, посмотри, сверь, повтори

Текстовая проверка не видит вёрстку. «Сборка прошла, тесты зелёные, 200 OK» ничего не говорит о том,
что шрифт упал в serif, заголовок обрезан, а обложка схлопнулась в ноль. Единственная настоящая
проверка экрана: отрендерить его тем же движком, что и в продакшене, открыть скриншот в контексте
и сравнить глазами с макетом. Проходов столько, сколько нужно до отсутствия расхождений: один, если
сошлось сразу, несколько, если нет; остановка по разделу «Когда остановиться», а не по счётчику.

## Когда запускать

- Любой экран из `docs/07-screens-and-ux.md` §1 и любое его состояние (загрузка, пусто, ошибка, нет доступа).
- Правка стилей, токенов в `design/README.md`, общих компонентов: затронуты все экраны, которые их используют.
- Нет макета продуктового экрана: останавливайся и спрашивай владельца. Сверять не с чем, а «примерно
  похоже» потом переделывается целиком. Служебные состояния (загрузка, пусто, ошибка, нет доступа) без
  макета делаются нейтрально в стиле соседних экранов (`design/README.md`) и сверяются только на
  отсутствие дефектов вёрстки.

Логику, права и деньги этот скилл не проверяет. Его результат (скриншоты) идёт как доказательство в
`verification-rubrics`, рубрика «экран».

## Инструменты набора

Основной путь, один экран за раз:

```bash
npm run dev                                  # in another terminal, DEV_LOGIN=1 in .env.local
node scripts/visual-check.mjs --only lesson  # 390x844, deviceScaleFactor 2, logged in via /api/dev/login
node scripts/visual-check.mjs --only lesson,profile --label m1   # into design/visual-check/m1/
```

Скрипт печатает путь к каждому PNG. Снимок полной страницы (`fullPage`), ждёт `networkidle` и
`document.fonts.ready`, а про горизонтальную прокрутку пишет `warning: ... scrolls horizontally`.
Это предупреждение не игнорируется: по `docs/07-screens-and-ux.md` §4 её нет ни на одном экране.

Нужен экран или состояние, которых нет в списке маршрутов: положи свою карту в `design/routes.json`
(имя → путь, либо `{ "path": ..., "auth": false }`) и передай `--routes design/routes.json`.

Для разовой проверки публичной страницы или статического файла хватает Playwright CLI:

```bash
npx playwright screenshot --viewport-size=390,844 --full-page --wait-for-timeout=3000 http://localhost:3000/login /tmp/login.png
npx playwright screenshot --viewport-size=360,740 --full-page <url> /tmp/narrow.png
npx playwright screenshot --viewport-size=390,844 --color-scheme=dark --full-page <url> /tmp/dark.png
```

CLI не умеет входить в систему и снимает в плотности ×1, поэтому для авторизованных экранов и для
сверки мелких деталей (толщина иконок, межстрочье) используй `visual-check.mjs`. Флаги CLI
сверяй с `npx playwright screenshot --help`: они меняются между версиями.

Эталон: `design/screens/NN-<экран>.png`. Соответствие ключа маршрута и файла макета в
`docs/07-screens-and-ux.md` §5 (`lesson_notes` ↔ `05-lesson-notes.png` и так далее).

## Цикл

1. Прочитай макет (Read на PNG) и выпиши в две-три строки, что на нём: блоки сверху вниз, шрифты,
   цвета, отступы. Недостающие токены занеси в `design/README.md` с пометкой «по макету».
2. Собери или поправь экран на демо-данных из `content/courses/example-course`.
3. Сними экран: `node scripts/visual-check.mjs --only <ключ> --label <этап>`.
4. Открой оба файла (Read макета, Read скриншота) и сравни по зонам, сверху вниз. Установка
   враждебная: считай, что криво, и найди все расхождения, а не подтверди сходство.
5. Исправь и вернись к шагу 3. Не правь вслепую по списку из десяти пунктов: после трёх-четырёх
   исправлений снимай заново, иначе одно исправление скрывает ошибку другого.
6. Остановись по условиям из раздела «Когда остановиться».
7. Сохрани финальные скриншоты как доказательство (раздел «Доказательства»).

## Как сравнивать два PNG в Claude Code

Прочитай оба файла подряд, сначала макет, потом скриншот, и сразу выпиши расхождения таблицей
по зонам. Не «в целом похоже», а по каждой зоне отдельная строка:

| Зона | Макет | Скриншот | Расхождение | Правка |
|---|---|---|---|---|
| шапка (заголовок, назад, аватар) | | | | |
| список или контент (строки, карточки, интервалы) | | | | |
| карточка (обложка, прогресс, цена, замок) | | | | |
| нижняя панель или футер (кнопки, навигация) | | | | |

Практические детали, на которых теряют время:

- Масштаб разный. Макет в 1170 px это 390 pt при ×3, скриншот в 780 px это 390 pt при ×2. Сравнивай
  пропорции и доли ширины экрана, а не пиксели: отступ 16 pt это 48 px на макете и 32 px на снимке.
- Длинный экран читается хуже: изображение при чтении ужимается, и мелочи пропадают. Режь на плитки
  высотой в один экран (1688 px при ×2) и читай по очереди: `magick in.png -crop 780x1688 +repage tile-%02d.png`
  (ImageMagick: `brew install imagemagick`). Один и тот же срез делай у макета и у снимка.
- Панель, закреплённая у нижнего края (`position: fixed`), в `fullPage` снимке стоит на месте
  первого экрана, а не внизу страницы. Это артефакт снимка. Её положение проверяй отдельным снимком
  вьюпорта (CLI без `--full-page`).
- Данные в макете могут отличаться (имена, цены). Расхождение в тексте данных не дефект; расхождение
  в размере, весе, цвете и отступе дефект.

## Каталог сигнатур слома

Читай скриншот по этому списку, пункт за пунктом:

- Заголовки в serif вместо гротеска: веб-шрифт не загрузился (путь в `@font-face`, нет кириллического
  сабсета, снимок сделан до `fonts.ready`). Первая причина «выглядит дёшево».
- Квадраты вместо букв: у шрифта нет кириллицы.
- Всё сдвинуто на одну величину: не тот базовый отступ, `box-sizing`, лишний `padding` у контейнера.
- Текст налезает на текст или обрезан: фиксированная высота, нет `min-width: 0` у flex-ребёнка,
  длинное название курса без переноса или `line-clamp`.
- Обложка или видео схлопнулись или прыгают: не задан `aspect-ratio`, блок ждёт загрузки картинки.
- Горизонтальная прокрутка (warning скрипта): элемент шире 390 pt, обычно изображение, таблица или
  длинное слово без переноса.
- Нижняя панель под полосой iPhone или под клавиатурой: нет `env(safe-area-inset-bottom)`, высота по
  `100vh` вместо `visualViewport`.
- Ритм отступов «дешевле» макета: не подхватились `line-height`, `letter-spacing`, шаг сетки. Самое
  частое «в целом верно, но не дотягивает».
- Цвет не из токена: оттенок чуть другой, потому что число вписано в компонент, а не взято из
  `--color-*`.
- Иконки другой толщины или размера, иконка из другого набора.
- Размыто: снимок в ×1 сравнивают с макетом в ×3. Это проблема сверки, не вёрстки.
- Скелетон остался на месте контента: снимок сделан раньше данных, либо запрос завис.
- Пустое состояние выглядит как сломанное: нет текста и кнопки, только белый экран.

## Свежий взгляд

Если ты правил один экран больше трёх кругов, глаз замылен. Передай сравнение субагенту через
Agent tool (тип `worker`) с коротким брифом: два пути (макет и скриншот), список зон из таблицы выше
и мандат «найди все расхождения, каждое с зоной и описанием, не чини». Полученный список
проверь сам по картинкам и исправляй по нему. Субагент, которому дали только скриншот без макета,
сходство подтвердит почти всегда, поэтому макет в брифе обязателен.

## Когда остановиться

Один из двух исходов, и оба записываются:

1. Расхождений нет, кроме текста данных. Последний круг прошёл по всем зонам таблицы без единой правки.
2. Остаток принял владелец: ты показал ему скриншот и макет, назвал оставшиеся различия
   списком, он ответил, что так можно. Запиши это в `PROJECT-STATE.md` с датой и перечнем.

Нельзя останавливаться по числу кругов или усталости. Нельзя считать экран сошедшимся, пока не
сняты все состояния из `docs/07-screens-and-ux.md` §3 и вторая ширина (360×740) без горизонтальной
прокрутки.

## Доказательства

Финальные скриншоты лежат в `design/visual-check/<этап>/` (`--label m1`, `--label m4-pay` и так далее)
и коммитятся вместе с кодом экрана. В коммит идут последние версии, промежуточные круги можно удалить.
Путь к папке записывается в `PROJECT-STATE.md` в строке этапа. Так владелец и ревью видят, на что
именно смотрели, а не верят на слово.

Форма отчёта по экрану, коротко:

```markdown
Экран: lesson (04-lesson-video) · кругов: 4 · эталон: design/screens/04-lesson-video.png
Скриншоты: design/visual-check/m1/lesson.png
Таблица зон: последний круг, расхождений нет / остаток: <список, принят владельцем <дата>>
Не проверено: <живой iPhone, тёмная тема, медленная сеть>
```

## Чего не делать

- Не объявлять экран готовым по логу скрипта: «файл создан» не значит «выглядит правильно».
- Не подгонять макет под код: меняется код, макет меняет только владелец.
- Не снимать только первый экран длинной страницы и не забывать вкладки, `<details>` и состояния.
- Не пользоваться движком, которого нет в продакшене (превью редактора, рендер в PDF-библиотеке):
  проверка идёт тем же Chromium, что и у скрипта.
