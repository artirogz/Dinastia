# Деплой на VPS: git, Compose, миграции, проверка, бэкапы

Пошаговая настройка сервера (пользователь `deploy`, SSH, межсетевой экран, домен, `.env`) лежит в
`docs/09-infra-and-deploy.md`. Этот скилл держит принципы, которые не дают выкату сломать данные, и
порядок действий при каждом релизе. Версии образов и флаги Docker и Caddy сверяй с актуальной
документацией до правки compose-файла.

Разрешения Claude Code в `.claude/settings.json` запрещают `ssh`, `infra/deploy.sh`, `infra/restore.sh` и
`docker compose -f infra/docker-compose.yml`. Это сделано намеренно: выкат и восстановление запускает
человек на сервере. Claude готовит команды, читает вывод, который ты вставил, и разбирает ошибки.

## Топология Compose

Файл `infra/docker-compose.yml`: `caddy`, `web`, `worker`, `postgres` и одноразовый `migrate`.

- Три сети. `edge` (caddy и web), `backend` (web, worker, migrate, postgres) с `internal: true`,
  `egress` (web и worker: исходящие вызовы к Telegram, ЮKassa, видеохостингу). У базы нет маршрута в
  интернет, а у caddy нет маршрута к базе.
- Наружу публикует порты только `caddy` (80, 443). Порт Postgres на хост не пробрасывается, даже на
  `127.0.0.1`: админ ходит в базу через `docker compose exec`.
- Секреты только в `infra/.env` на сервере. Файл не в git, не в образе, не в логах. Каждая переменная
  описана в `infra/.env.example`.
- В проде `NODE_ENV=production` и `DEV_LOGIN=0`. Smoke проверяет, что `/api/dev/login` отдаёт 404.
- Версия образа неизменяема: `courses-app:<короткий sha>`. Тег `latest` не используется, иначе
  откатываться не к чему. Подвижный `courses-app:current` (его ставит `deploy.sh`) нужен только командам
  без версии (`backup.sh`, `restore.sh`, `compose logs`); выкатывается и откатывается всегда sha-тег.
- У `web`, `worker` и `postgres` есть healthcheck, у всех сервисов ротация логов. `web` не получает трафик, пока не стал healthy.

## Как идёт выкат

Сервер держит клон репозитория (`/opt/courses`), выкат делается из него. Код попадает на сервер только
через git, правки руками на сервере запрещены: следующий `git pull` их затрёт, а пока они живы,
в проде работает код, которого нет ни в одном коммите.

```bash
ssh deploy@<ip>
cd /opt/courses && infra/deploy.sh
```

Что делает `deploy.sh`, по порядку: `git pull --ff-only origin main` → сборка образа с тегом по sha из
временной копии репозитория (с проверкой `infra/check-runtime.mjs`) → запуск `postgres` → бэкап перед
миграциями → запись `infra/.release/candidate` → `migrate` (одноразовый контейнер) → запуск `web` и
`worker` → ожидание healthy → smoke против боевого адреса → запись версии в `infra/.release/current`.
Провал health или smoke возвращает последнюю версию, прошедшую smoke; `current` и `previous` при этом не
меняются. Скрипт останавливается на первой ошибке и не идёт дальше с предположением «наверное,
нормально». Полное описание, включая таблицу файлов `infra/.release/`: `docs/09-infra-and-deploy.md` §6–§7.

Перед выкатом: всё нужное в `main` и запушено, ревью пройдено, локально зелёные `npm run typecheck` и
`npm test`. Выкатывай пакетом из нескольких готовых задач, а не каждую правку отдельно.

## Миграции

- Миграции из `src/db/` накатывает контейнер `migrate` до старта `web` и `worker`. Повторный запуск на
  уже накатанной базе ничего не меняет (журнал Drizzle хранит применённые файлы).
- Каждая миграция совместима с предыдущей версией кода. Порядок «расширить, перейти, сжать»: релиз 1
  добавляет колонку (nullable или с дефолтом), релиз 2 начинает ей пользоваться, релиз 3 удаляет старое.
  Тогда откат на одну версию безопасен.
- Миграция, ломающая прошлую версию (переименование, удаление, смена типа), требует отдельного плана,
  свежего бэкапа и окна, не пятницы вечером.
- Репетиция на копии: восстанови последний дамп в соседнюю базу (`infra/restore.sh <dump>` без флагов
  делает именно это) и накати на неё новую миграцию вручную. Это ловит то, чего не видят юнит-тесты на
  пустой базе: настоящие данные, нарушающие новое ограничение, и долгие блокировки на больших таблицах.
- Образ базы в проде и в локальной разработке одной мажорной версии (`postgres:16-alpine`). Расширения
  (если появятся) входят в образ, а не ставятся руками в работающий контейнер.

## Проверка после выката: вердикт из артефакта

Выкат считается завершённым не по коду возврата скрипта, а по файлу, который пишет сама проверка:
`infra/.last-smoke.txt`. В нём заголовок с временем и версией образа и построчный вывод
`scripts/smoke.mjs`; пишет его `run_smoke` в `infra/deploy.sh`.

Релиз принят, когда одновременно верно следующее:

```bash
head -1 infra/.last-smoke.txt                 # the version in the header equals infra/.release/current
grep -c '^FAIL' infra/.last-smoke.txt         # 0
tail -1 infra/.last-smoke.txt                 # all checks passed
```

Файл не коммитится. Вывод команд выше вставляется в отчёт о выкате: «smoke прошёл» без вывода не
доказательство. После smoke открой боевой адрес сам: `/start`, меню, открыть приложение, урок.
Для денег пока боевой магазин не включён используется тестовый платёж (`verification-rubrics`, рубрика
«деплой»).

## Бэкапы

- Ночью по cron `infra/backup.sh`: `pg_dump -Fc`, проверка дампа через `pg_restore --list`, копия дампа
  через `rclone` в S3-хранилище российского провайдера, зеркало каталога медиа в `media/current` с
  переносом удалённых файлов в `media/deleted/<дата-время>`, удаление дампов и папок `deleted` старше
  `BACKUP_RETENTION_DAYS` (14). Тот же скрипт вызывается из `deploy.sh` перед миграцией.
- Ключи медиафайлов неизменяемы (`docs/02-data-model.md`, `file_key`): только так медиа на дату дампа
  восстанавливаются точно (`docs/09-infra-and-deploy.md` §8).
- Копия на том же сервере не бэкап: она гибнет вместе с ним. Хранилище должно быть другим аккаунтом, а
  лучше другим провайдером. Скрипт предупреждает, если `BACKUP_RCLONE_REMOTE` пуст.
- В дампе персональные данные. Бакет приватный, ключ доступа только на запись и чтение этого бакета, а
  шифрование перед выгрузкой (`rclone crypt` или `age`, приватный ключ вне сервера) включается решением,
  записанным в `docs/11-decisions.md`.
- Контроль «бэкап вообще идёт»: Push-монитор в Uptime Kuma, URL в `BACKUP_HEARTBEAT_URL`. Скрипт стучится
  только после полного успеха, пропуск суток краснит монитор.
- Файл `infra/.env` в бэкап не входит и хранится в менеджере паролей владельца.

### Тренировка восстановления раз в месяц

Бэкап, который ни разу не восстанавливали, считается несуществующим.

```bash
ls -t /srv/courses/backups/*.dump | head -1
infra/restore.sh /srv/courses/backups/<file>.dump --drop   # scratch database, row counts, then dropped
```

Сверь числа строк (users, courses, lessons, orders, entitlements, progress) с боевой базой. Нули или
сильное расхождение означают сломанный бэкап. Запиши в `PROJECT-STATE.md` дату, имя дампа и время
восстановления: это и есть твоя цифра «сколько мы простоим при аварии». Настоящая авария идёт по
`docs/09-infra-and-deploy.md` §8 «Восстановление после аварии»: `infra/restore.sh <dump> --into-live`
восстанавливает копию рядом с боевой базой, переключает базы переименованием после подтверждения
(старая сохраняется) и запускает только `web`. Воркер стартует руками после сверки платежей и списка
повторных отправок.

## Откат

```bash
infra/deploy.sh rollback
```

Неудачный выкат откатывается сам на `infra/.release/current`. `rollback` нужен, когда версия прошла
smoke, а ошибка нашлась позже: он поднимает `infra/.release/previous`, ждёт healthy и гоняет smoke.
Любой другой коммит: `infra/deploy.sh --sha <commit>`, образ пересоберётся, если его уже нет.
Миграции назад не откатываются, поэтому они совместимы на одну версию.
Сломан код: откат версии. Сломаны данные: откат версии не поможет, нужно восстановление из бэкапа.

## Чек-лист каждого выката

- [ ] Нужные коммиты в `main` на GitHub, локальные `typecheck` и `test` зелёные.
- [ ] Для миграции: репетиция на копии боевой базы, совместимость с прошлой версией, свежий бэкап.
- [ ] Выкат прошёл, версия в `infra/.release/current` совпадает с ожидаемым sha.
- [ ] `infra/.last-smoke.txt`: заголовок с этой версией, ноль `FAIL`, последняя строка `all checks passed`.
- [ ] `docker compose ... ps`: `web` и `worker` healthy, `migrate` завершился с кодом 0.
- [ ] Живой путь на проде пройден вручную, для UI есть скриншот.
- [ ] `getWebhookInfo` без `last_error_message`, сверка платежей пишет строку в лог.
- [ ] Запись в `PROJECT-STATE.md`: версия, дата, что выкачено.

## Чего не делать

- Не править код и конфиги на сервере: только через git и `deploy.sh`.
- Не публиковать порты, кроме 80 и 443 у `caddy`.
- Не запускать `docker compose down -v` и `docker volume rm` на проде: это удаляет `pgdata`.
- Не пропускать бэкап перед миграцией флагом `--no-backup`, кроме выката на самый первый раз.
- Не считать зелёный `docker compose up` доказательством: решает smoke и живой путь.
- Не выкатывать миграцию, ломающую прошлую версию, одним релизом вместе с кодом.
