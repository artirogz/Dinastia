# CLAUDE.md — платформа курсов в Telegram (Mini App + бот)

Это стартовый пакет: архитектура, модель данных, правила и рабочий процесс для платформы онлайн-курсов,
которая живёт в Telegram Mini App и управляется ботом (прогревы, оплата, выдача доступа).
Кода приложения здесь ещё нет. Он создаётся по этим документам.

> Это маршрутизатор, не хранилище. Читай только то, что нужно для текущей задачи (список ниже).

## Первый запуск

Пока в корне нет `package.json`, любое первое сообщение владельца («Начинаем работу над проектом»,
стартовый промпт из README, «стартуем», «поехали») означает скилл `start-project`. Он сам проверяет и
ставит окружение на Mac (Homebrew, Node, Git, Docker), делает `git init` и первый коммит, задаёт
вопросы, создаёт структуру, ставит Next.js, базу и Playwright и заканчивает первым скриншотом.
Владельца о ручных действиях просят только там, где без него нельзя (пароль для установщика
Homebrew, значения секретов в `.env.local`). Не начинай писать код приложения, пока скилл не отработал.

## Структура репозитория (после старта)

```
src/app/              Next.js App Router: экраны мини-аппа и API-роуты
src/app/api/          серверные ручки (auth, lessons, progress, comments, payments, tg/webhook)
src/bot/              grammY: команды, меню, сцены оплаты, админ-команды
src/worker/           фоновый процесс: шаги прогревов, рассылки, сверка платежей
src/lib/              lessons.ts (единственная дверь к уроку), access.ts, видео-провайдер, платежи, подпись initData
src/db/               Drizzle: schema.ts, миграции, клиент
src/components/       UI-компоненты экранов
content/courses/      курсы и уроки файлами (yaml + markdown), импорт в базу скриптом
scripts/              visual-check.mjs (скриншоты экранов), smoke.mjs (проверка прода), import-content.ts, admin.ts (операции владельца без бота)
infra/                docker-compose.yml, Caddyfile, .env.example, backup.sh
design/               скриншоты макетов и токены дизайна
docs/                 документы этого пакета
tests/                vitest: подпись initData, доступ к урокам, flip статуса оплаты
```

## Правила проекта

**Персональные данные остаются в России.** База, файлы, логи и резервные копии живут на российском
VPS. Зарубежные сервисы допустимы только для того, что не содержит персональных данных (видео на
видеохостинге без имён пользователей). Подробности и список запретов — `docs/03-auth-and-security.md`.

**Контент урока выходит из одной функции.** Видео, конспект, материалы и задание страница, server
action или API получают только от `getLessonForUser()` из `src/lib/lessons.ts`; внутри неё
`requireLessonAccess()` (курс, публикация, порядок разблокировки). Чтение таблиц уроков или `getPlayback()`
в любом другом файле `src/**` ловит тест-сканер `tests/access-invariant.test.ts`
(`docs/01-architecture.md` §8, инвариант 1).

**Идентификатор пользователя берётся только из проверенной сессии.** `tg_id` из тела запроса или
query-параметра не принимается никогда.

**Оплата отмечается атомарно и один раз.** Вебхук ЮKassa и фоновая сверка зовут один обработчик;
доступ выдаёт только тот вызов, который реально перевёл заказ из `pending` в `succeeded`.

**Ничего не отправляется пользователям без явного действия владельца.** Рассылка и запуск
прогрева стартуют по команде администратора в боте, не автоматически после деплоя.

**Дизайн воссоздаётся по скриншотам владельца.** Любой экран закрывается скиллом
`visual-fidelity-loop`: Playwright делает скриншот в 390×844, Claude открывает его и сравнивает
с макетом. «Собралось без ошибок» не считается готовым экраном.

**Секреты только в `.env`.** Токен бота, ключи ЮKassa, ключ видеохостинга, строка подключения к базе.
В код не попадают, в git не коммитятся.

## Команды (появятся после `start-project`)

```bash
npm run dev                 # мини-апп локально, вход через /api/dev/login
npm test                    # vitest
npm run typecheck           # tsc --noEmit
npm run db:generate         # drizzle-kit: миграция из schema.ts
npm run db:migrate          # применить миграции из ./drizzle
npm run build:server        # esbuild: worker, migrate, import-content, admin → dist/
npm run content:import      # content/courses → база
node scripts/visual-check.mjs           # скриншоты всех экранов в design/visual-check/
node scripts/smoke.mjs https://<домен>  # проверка живого прода
```

## Процесс

Каждая задача начинается со скилла `dev-flow-lite`: он выбирает, сколько процесса нужно
(правка → мини-план → спека с ревью), и какие проверки обязательны на выходе. Деньги, вход,
вебхуки и миграции всегда проходят ревью отдельной сессией, даже если правка в три строки.

Экономия токенов: `docs/10-working-with-claude.md`. Коротко: Sonnet для реализации, Opus для
архитектуры и ревью; не читать деревья файлов целиком; `/compact` после каждого этапа.
